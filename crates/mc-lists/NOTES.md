Structural functions work on any compound term (`length(a+b)` is 2, `rest(f(a,b,c))` is `f(b,c)`). Modules:
`construct`, `access`, `reshape`, `reduce`, `select`, `matching`, `sort`, `measure`, `strings`, and `ctx` (shared
symbols, failure builders, fuel meter, calling function-valued arguments). Every function is one native type
(`Fun { lib: Arc<Lib>, body: fn }`) holding only symbols and a flag (nothing to trace). Function-valued arguments are
called with `cx.eval(f(x))`; `select` and `array` evaluate their calls as a speculative `cx.group`, like `map`.

## Decisions

- **I.1** `install(k, h, stop)`: `Kernel::register` needs `Sym`s from the heap, and `sum`/`product`/`range` call
  `mc_arith::Arith`, which polls only the flag it is given (mirrors `mc_engine::arith::install`).
- **I.2** Every function is strict (the pattern of `cases`/`count` is evaluated, see I.13).
- **I.3** A result with head `list` is returned as `Done`; any other rebuilt head as `Again`, so canonicalisation and
  rules apply (`append(x + 1, 2)` gives `3 + x`).
- **I.4** Fuel: per-element work costs 1 unit per 16 elements, charged in chunks of 4096 (each charge polls the
  interrupt); pure copies charged once, before the copy; each call of a function argument costs `tick(1)` plus the
  evaluator's charge.
- **I.5** Failures: `failure(index, i, n)` (atoms have n = 0), `failure(argument, f, k)`,
  `failure(shape_mismatch, transpose)`, `failure(limit, memory, call)`; a symbol where a list or index is expected, or
  a symbolic index, leaves the call unevaluated (`y[1]`, `xs[k]`, `range(x)`).
- **I.6** Built results are capped at 2^28 elements.
- **I.7** Inexact `range` elements are `a + k·step` in the most inexact kind (no accumulated rounding); the count
  tolerates 8·eps relative error (`range(0, 0.3, 0.1)` has 4 elements); exact bounds stay exact.
- **I.8** `sum`/`product`: machine integers folded in 128 bits; other exact numbers by a balanced tree of `Arith`
  calls; everything else in a single `Arith::add`/`mul` with the exact total (one canonical `add` however many terms).
- **I.9** `total(xs)` sums every leaf of the nested lists (not a level-1 elementwise vector sum).
- **I.10** `cases`/`count` use a local continuation-passing matcher (natives cannot compile patterns: request 1):
  backtracking sequence variables, recursion only on the pattern (depth 256, 4096 nodes), checked first with
  `mc_eval::syntax::pattern`; supports `_`, `x_`, `x_: T`, `x__`, `x___`, `x @ p`, `p when c`, `|`; AC heads matched
  positionally against the canonical order (incomplete).
- **I.11** `select` keeps an element only when the predicate gives `true`; a failure from the predicate is the result.
- **I.12** Sorting uses `mc_arith::Order` (the engine's hook; `NativeCx` cannot reach the kernel's hook) through a local
  comparator that decides integers, strings, symbols and kinds directly; one stable, interruptible merge sort that only
  asks whether b must come before a.
- **I.13** A pattern variable with a global own value spoils the evaluated pattern: `failure(argument, cases, 2)`.

## Contract changes needed (local workarounds in place)

1. `NativeCx::compile_pattern(&self, Pat) -> Result<Pattern, DefError>` (or from a term), so `cases`/`count` use the
   evaluator's matcher (AC matching, effect refusal in conditions) and `matching.rs` can go.
2. The kernel's order for natives: `NativeCx::cmp(a, b)` / `NativeCx::sort(&mut [T])`.
3. One way for libraries to get the arith stop flag (for example held by the `Kernel`), so `install` does not need
   I.1's signature.

## Known gaps

- AC matching in `cases` is positional, and its conditions do not run under the evaluator's effect refusal (request 1).
- `cases`/`count` look at level 1 only; no listability or elementwise list arithmetic; `max`/`min` decide only reals.
- `array` is one-dimensional; no `table`; sorting is sequential; `sort(xs, by)` makes about n·log n interpreted calls.
- `nest` with deep results relies on the memo (with it off, the depth limit F.11 is reached).
- Sums of 10^6 rationals are limited by `mc-arith`'s gcd (no subquadratic algorithm).
- `to_string` carries a local copy of the engine's 10-line number format.

## Item 1A (roadmap phase 1: predicates and structure)

Every 1A target is built with a `FUNCTIONS` entry and tests; clippy clean. Registration through the existing
`mc_lists::install` (no `mc-engine` edits). Together with the compiler, the JIT test's `inner`/`outer` user functions were renamed
(`inc`, `twice_inc`: `inner` and `outer` are now natives) and 1B's `a[k]` tests moved to key semantics (1A.16).

### What was built (new modules)

- `predicates`: kinds `is_integer`, `is_rational`, `is_number`, `is_exact`, `is_inexact`, `is_machine_number`,
  `is_string`, `is_symbol`, `is_atom`; shapes `is_list`, `is_vector(v[, test])`, `is_matrix(m[, test])`; quantifiers
  `all_true`, `any_true`, `none_true` (stop at the first deciding element).
- `search`: `free_of(t, p)` (every depth, heads included, each distinct subterm once), `member_of(xs, p)` (level 1),
  `position(t, p)` (index lists for `part`), `select_first(xs, f[, d])`; patterns through `NativeCx::compile_pattern`
  and `matches` (AC matching, effect-refusing conditions); a pattern without constructs compares by identity.
- `arrange`: `riffle`, `catenate`, `partition(xs, n[, d])`, `rotate_left`/`rotate_right(xs[, k])`,
  `pad_left`/`pad_right(xs, n[, x])`, `constant_array(c, n | [dims])` (shared rows), `thread(f(...))`.
- `group`: `tally`, `gather`, `gather_by(xs, f[, r])`, `unique_by`, `count_by` (rules `k -> n`), one hash-map pass each.
- `combinat`: `subsets(xs[, n | [n] | [a, b]])`, `tuples(xs, n)` and `tuples([xs1, ...])`, `permutations(xs[, spec])`,
  `outer(f, xs, ...)`, `inner(f, a, b[, g])`.
- `sort` additions: `sort_by`, `ordering(xs[, n])`, `max_by`, `min_by` (kernel order, `NativeCx::cmp`); the merge sort is
  generic over its element type.
- `construct` additions: `table` (all arguments held; `table(e, n)`, `table(e, k, r)`, more `k, r` pairs for nesting),
  `array(f, [n1, ..., nd])`, `map_indexed`, `map_thread`, `scan`.
- `ctx` helpers: `keys`, `truth`, `count_operand`, `dims_operand`, `cells`, `nest_flat`, `shape`, `rule`, `MAX_CELLS`.

### Decisions

- **1A.1** Kind predicates always answer `true`/`false` (a symbol is not an unknown number: `is_integer(n)` is false).
- **1A.2** `is_rational` means an exact real (integers count).
- **1A.3** `is_atom(1 + 2im)` is false: a complex number is the compound `complex(re, im)` (consistent with `length`
  and `part`; a deliberate choice).
- **1A.4** Combinatorial and array results over `MAX_CELLS` = 2^26 argument slots (all levels) are refused before
  allocation with `failure(limit, memory, call)` (`subsets`, `tuples`, `permutations` by an exponential-generating-
  function estimate plus a guard while building, `outer`, `inner`, `array`, `constant_array`, `table`, `partition`);
  `array(f, n)` now refuses n above 2^26.
- **1A.5** Pattern searches use the evaluator's compiled patterns; `cases` and `count` still use the local matcher.
- **1A.6** `position` lists a part after its head and arguments, arguments in order (`position([[a]], _)` is
  `[[0], [1, 0], [1, 1], [1], []]`).
- **1A.7** Groups in the order of their first element, compared by identity.
- **1A.8** No list-form `group_by` (1B's association form owns the name); the list form is `gather_by(xs, f[, r])`.
- **1A.9** `delete_duplicates_by` is `unique_by` (the `by` form of `unique`).
- **1A.10** `riffle(xs, ys)` with a list `ys` needs length n or n - 1, else `failure(shape_mismatch, riffle)` (no
  cycling).
- **1A.11** The padding element is used as is, even a list (no cyclic padding).
- **1A.12** `permutations` gives distinct arrangements, lexicographic by position, each at its first occurrence.
- **1A.13** `outer` uses the first level of each list.
- **1A.14** `table` is held and built as the closure `fn([k], e)` (lexical, hygienic: with a global `k = 10`,
  `table(k, k, 3)` is `[1, 2, 3]`); elements evaluated as a group like `map`; a range is a list or an integer n
  (1..n); a symbolic range leaves the call unevaluated.
- **1A.15** `map_indexed` passes an integer index `f(x, i)`.
- **1A.16** `part` declines when its first argument is an `assoc(...)` call (so 1B's rules handle every key).
- Also: `max_by`/`min_by` return the first extreme element (empty list: `failure(index, 1, 0)`); `select_first` with no
  match and no default is `failure(not_found, select_first)`; `inner` handles up to matrices; a failure from a
  predicate or key function is the result.

Edit outside the crate: `mc-kernel/tests/protocol.rs` (completion of `uniq` is `["unique", "unique_by"]`).

## Round 16 (item 9B, part 2)

- **C9B2.l1 `riffle` at positions.** `riffle(xs, s, n)` puts `s` at every `n`-th place of the result,
  `riffle(xs, s, [i, j, k])` at the places `i, i + k, ...` up to `j` (negative places count from the end, a

## Round 17

Tests: `mc-engine/tests/r17_fixes.rs` (5 tests, through the whole engine; also the kernel features of that round, `unset`, `protect`, the

- **r17fix.7 Strings sort alphabetically.** `sort`, `ordering`, `sort_by` and the other users of `sort.rs`'s
  comparison order strings with letter case folded first, then lower case before upper case at the first
  difference, then by code points (the primary and tertiary levels of UTS #10 without its tables): `["cat", "Cat",
  "catfish", "fish"]`, as people read word lists. This departs from the canonical order of
  semantics 8 (code points) for strings only; `Canonical` is otherwise still identical to `mc_arith::Order` (the
  unit test compares them on terms whose strings have no case differences). Accented and non-Latin letters keep
  their code-point place (`"é"` after `"z"`): no locale tables.
- **`hash(e[, method[, format]])`** (`src/hash.rs`): MD5 (RFC 1321), SHA-1, SHA-224, SHA-256, SHA-384, SHA-512
  (FIPS 180-4), CRC-32 (ISO 3309), Adler-32 (RFC 1950), implemented from the specifications and checked against
  their published test vectors; strings hash as UTF-8 bytes, other terms as the bytes of `to_string`; `"Expression"`
  (the default) is the kernel's structural hash; formats `"Integer"`, `"HexString"`, `"DecimalString"`,
  `"ByteList"`. Digests of strings are the standard digests of their UTF-8 bytes (those of other terms depend on
  `to_string`).
- Forms that left calls unevaluated before: `first(xs, d)`/`last(xs, d)` (a default for an empty list;
  evaluated like every argument); `level(x, spec, heads: true)` (heads as parts, `levels::with_heads`);
  `position_largest`/`position_smallest` with `n` (the positions of the `n` extreme distinct values, grouped,
  largest first with positions in decreasing order) and on associations, without `n` a flat list
  of integer positions (was `[[i], ...]`); numeric constants are numbers there;
  `power_range(b)` and symbolic `power_range(a, b, r)` (terms up to the one equal to `b`); `count_distinct(xs, f)`
  (the classes of `unique(xs, f)`); `thread(x, g, spec)` with a sequence specification; `array(f, n, [a, b])`
  (equally spaced points), per-dimension origins and ranges, and a head `array(f, dims, r, g)`; `dimensions(x, n)`
  and `allowed_heads:`; `comap(fs, x, levels)`; spans with `all` and `up_to(k)` ends and an `all` step;
  `take_largest`/`take_smallest` leave out `none`, `indeterminate` and `missing(...)` (option `excluded_forms:`);
  `leaf_count(x, heads: false)`; `value_q(x, method: ...)` (`"TrialEvaluation"`, `"OwnValuesPresent"`,
  `"SymbolDefinitionsPresent"`, `automatic`).
- **`groupings(xs, spec)`** (`src/groupings.rs`): every tree of calls over the elements in order, for arities and
  heads (`k`, `[k1, ...]`, `h -> k`, `[h1, h2] -> k`, lists of rules, `orderless`, one-argument heads as wrappers).
  The order: fewer calls first, then root head
  in the given order, root part sizes as decreasing partitions, part shapes recursively in this order, positions of
  the larger parts from the left; an orderless head takes one arrangement of its parts. Shapes are built once per

  binary trees) take about 0.2 s.

## Round 18 phase 9B

Tests: `tests/core_round18.rs` (natives on source text; the prelude functions through the whole engine), the
documentation pages of every new function.

- **P9B.1 Subsets matching list patterns** (`src/subsets.rs`): `subset_cases`, `subset_position`,
  `subset_replace` match a list pattern `[p1, ..., pk]` against elements of `xs` taken in any order. Position
  tuples are enumerated depth first, each slot taking the free positions in increasing order, so the first tuple
  found for a subset is the least in the lexicographic order of tuples; a subset (as a set of positions) is found
  once. Runs (`__`, `repeated`) take subsets of every size they allow, the largest first. Without overlaps (the
  default of `subset_cases` and `subset_replace`; `subset_position` lists every subset) a match uses up its
  positions (a greedy cover in that order); `[a] | [__]` tries the alternatives in turn on what is left. Slots that
  stand for one element are tested alone first, a necessary condition that prunes the search; the whole list is
  then matched by the evaluator's matcher, so conditions and shared variables mean what they mean in rules.
  `subset_replace` puts the right side where the element matching the first slot was and removes the subset's other
  elements. At most
  2,000,000 candidates per call: past that the call stays unevaluated rather than running unboundedly.
- **P9B.2 Ordering functions in `sort` and `ordered`.** A predicate that gives 1, 0 or -1 (`order`,
  `alphabetic_order`, `numerical_order`, `lexicographic_order`) is read so: -1 puts the later element first in `sort`; 1 and 0 hold in `ordered`; only 1 is a strict
  "before" in `ordering`'s comparisons. `true`/`false` predicates are unchanged.

## Round 37: argument forms

- **r37.2** `join(xs, ys, ..., n)`: an integer n >= 2 after two or more operands joins the corresponding parts at
  level n; ragged operands contribute where they reach (`join([[x]], [[1, 2], [3, 4]], 2)` is `[[x, 1, 2], [3, 4]]`).
- **r37.3** `delete_elements(xs, n -> es)`: at most n (or inf) occurrences of each element, the first ones; a list
  n gives a count per element, and the counts of a repeated element add up.
- **r37.4** Size ranges `[a, b, s]` in `subsets` and `permutations` (a negative step counts down; sizes above the
  length are left out). Operands with another head keep it, as `subsets` already did:
  `partition`, `permutations`, `tuples(xs, n)`, `fold`, `fold_list`, `symmetric_difference`, `pad_left`/`pad_right`
  with one length; `block_map` of such a term gives the list of the f(block)s. `tuples(xs, [n1, ..., nk])` gives
  arrays of those dimensions. A negative length pads at the other end (`pad_left(xs, -n)` is `pad_right(xs, n)`).
  `fold_list(f, [])` is `[]`. A vector of numbers is its own `transpose` (`conjugate_transpose` of a vector is its
  conjugate). Not done: `partition` with a list of sizes of a term with another head (the general partition still
  takes lists only), `block_map` with a list of sizes of such a term.
- **r37.6** `total(xs, -k)`: negative levels count from the leaves of the full array of lists (-1 the deepest):
  levels 1 to d + 1 - k of an array of depth d; `total(xs, [a, b])` adds levels a to b (each may be negative): the
  totals at levels a - 1 to b - 1 of each element when a > 1. A level outside the array declines.
- **r37.7** `apply(f, x, levels, heads: true)`: the heads of compound parts are parts one level below their call, as
  for `map` (`apply(f, p(x)(q(y)), [1], heads: true)` is `f(x)(f(y))`); `heads: false` is the plain apply.
- `variance(weighted_data(d, w))` and `std_dev` (lib/lists.mc): sum w (d - m)^2 / sum w with m the weighted mean,
  the variance of the distribution the weights put on the values (frequency weights, no n - 1 correction); numbers by two passes, symbolic weights as (W sum w d^2 - (sum w d)^2) / W^2 with the
  numerator expanded.
- `alphabetic_order(lang)` and `alphabetic_sort(xs, lang)` for Slovak, Spanish, Swedish and Serbian (lib/prelude.mc):
  the tailorings of the Unicode CLDR collation for the Latin script as data (a unit, a letter or a digraph, sorts
  as a letter of its own after a base letter: Slovak ä č ch ô š ž, Spanish ñ, Swedish å ä/æ ö/ø after z and ü as
  y); first-level weights compared lexicographically, ties by the root order. Serbian tailors only Cyrillic, so its
  Latin order is the root order. Other languages (Danish, Turkish, Dutch) and the options `case_ordering`,
  `ignore_case`, `ignore_diacritics`, `ignore_punctuation` are not done (no table): those calls stay unevaluated.
  `key_sort(a, p)` sorts the keys by an ordering function.
- `dimensions` and `array_depth` with `allowed_heads: full`: the parts of a level may have different heads.
- `subsequences(xs, spec, m)`: the first m runs, `up_to(m)`, `[k]`, `[a, b]` or `[a, b, s]` (s may be negative) of
  the runs in their order; a position past the end declines. `map_indexed(f, x, levels, heads: true)`: the heads
  are parts at position 0 of their calls, positions as index lists. Not done: `delete_cases(..., heads: true)`
  (deleting a head splices its arguments into the parent: sequence splicing, a user decision against it).

## Round 37 integration

- **An `options(...)` operand is data.** `ctx::option(h, args, positional, name)` takes the number of arguments the
  function always has: a final `options(...)` among them is an operand, not the call's options. Before, `apply`'s
  new `heads:` option (r37.7) took the operand of `apply(list, o)` with `o = options(size: 2)` for its own options,
  dropped it and declined: every library function that reads its options with `apply(list, o)` lost them
  (`nest_graph` `directed_edges`, `n_roots` `precision_goal`, the option checks of `lib/calculus.mc` and
  `lib/numerics.mc`). The same held for every native with an option (`leaf_count`, `cases`, `count`, `position`,
  `first_case`, `level`, `map`, `map_indexed`, `dimensions`, ...) given an `options(...)` operand. Test
  `r37_f37c_integration::options_reach_library_functions_every_way`.
- **A call given settings is no container** (`Lib::elements_operand`, for the operations of decision r37.4 on other
  heads: `partition`, `tuples`, `permutations`, `fold`, `fold_list`, `symmetric_difference`): a non-list whose last
  argument is `options(...)` is an argument error, as any non-list was before. `accumulate(time_series(ts,
  temporal_regularity: true))` had added the settings to the data (`time_series(ts, ts + options(...))`).

## Round 38: arrays, subset counts, tours, symbols by name, cleanup

- `array_filter(f, a, r)` (`arrays.rs`): blocks of radius r (a count, per-level radii, or `[before, after]` pairs)
  around every element of the full array; padding "Fixed" (edge repeated, default), "Periodic", "Reflected" or a
  value. A radius list longer than the array's depth (a kernel array) is not read: the call stays unevaluated.
- `array_reduce(f, a, n | [n1, ...])`: f of each vector (sub-array) along the levels, those levels removed.
- `subset_count`: the number of subsets `subset_cases` gives (disjoint by default), in `subsets.rs`.
- `find_shortest_tour` (`tour.rs`): exact dynamic programming over subsets (Bellman 1962; Held and Karp 1962) for up
  to 20 elements; more stay unevaluated rather than giving a heuristic tour as the shortest. Euclidean distance,
  `abs(x - y)`, edit distance (Levenshtein 1966) of strings, or `distance_function:` (`inf` is no step; no finite
  tour gives `failure(not_found, ...)`). The minimum is decided in machine arithmetic, the length returned is the
  exact sum along the tour; of the two directions of a symmetric tour the one with the smaller second index.
- `symbol(name)` reads the name with the reader (keywords and expressions are `failure(argument, symbol, 1)`);
  `symbol_name(x)` drops the module path.
- `with_cleanup(body, cleanup)`, `(init, body, cleanup)`: held; the cleanup runs after a value or a failure (a throw);
  an interrupt or limit stops it too.
- `free_of` with `verbatim(p)`: the literal probe is the term inside `verbatim` (search.rs `Probe::new`).
- Gap seen: `box_matrix(0, [n, n])` gives `failure(division_by_zero)` entries (not changed here).
## Round 38: argument forms of list functions

- **Heads as parts** (`heads: true`, `ctx::heads_flag`): `map_all` maps the heads too; `map_apply`, `comap` and
  `comap_apply` treat the head as a level-1 part (`comap(h(a), x, heads: true)` is `h(x)(a(x))`); `depth` counts a
  head one level below its call; `replace_part` lets position patterns reach index 0 (`heads: false` keeps every
  head, also for an explicit 0); `member_of(x, p, levels, heads: true)` counts as `count` does. An options term with
  any other key declines. Associations decline with `heads: true` (their head is not a part of their tree).
- **`transpose(a, [p1, ..., pk])`** (`reshape::transpose_levels`): level i of the full array goes to level p_i; part
  [j1, ..., jm] of the result is part [j_p1, ..., j_pk] of a; an index named twice runs along the diagonal of the
  shorter length (`transpose(m, [1, 1])` the diagonal). The p_i must cover 1..m. `conjugate_transpose(a, perm)` is
  its conjugate.
- **Ordering functions**: `take_largest(xs, n, p)`, `take_smallest`, `position_largest(xs, n, p)`,
  `position_smallest`, `ordering_by(xs, f, k, p)`, `reverse_sort_by(xs, f, p)` order by p as `ordering(xs, all, p)`
  does; the "largest" are the last in that order. Position groups join elements p does not separate (p gives 0, or
  a predicate false both ways). With the canonical `order` the result follows MathCAS's canonical order (consistent
  with `sort` and `reverse_sort`), which differs from other systems' for terms such as `-inf`.
- **Counts**: `up_to(k)` in `ordering`, `commonest`, `cases(x, p, levels, up_to(k))` and `string_take`; `ordering(xs,
  [m, n])` takes positions m to n of the ordering.
- **Margins and steps**: `pad_left(xs, n, x, m)` and `pad_right` leave m copies of x at the other end (a non-list
  padding element); `take` and `drop` accept a negative step (`[-1, 1, -2]`).
- **Indexed table variables**: `table(e, a(x), n)` and `table(e, x(1), 3, x(2), 3)`: a call of a symbol without
  definitions, its arguments atoms, in a variable's place is replaced by a fresh symbol (iterator lists keep their
  one place in the walk, so a bound such as `g(i)` after `[i, 3]` is never taken for a variable).
- **Sets of array heads**: `dimensions` and `array_depth` with `allowed_heads: [h1, h2]` (each level one head of the
  set) or `h1 | h2` (heads of the set mixed within a level); `numeric_array(data, type)` and `byte_array(data)` hold
  the elements of their data.
- `delete_missing(xs, n)` down to level n; `delete_missing(xs, n, d)` drops the elements at levels 1..n holding a
  `missing` at most d levels inside (lists and associations only). `all_true`, `any_true`, `none_true` on an
  unexpanded `sparse_array(rules, dims[, background])` test the explicit values and the background when a position
  is left (no expansion of 10^12 elements). `string_length` of a list of strings; `map_at` and `replace_at` with
  `all` in a position; `replace_at` with an association of rules; multi-level rotation of associations.
- `box_matrix`, `disk_matrix`, `diamond_matrix`, `cross_matrix` with a radius 0: the offset in units of the radius
  was o/r; a zero radius holds only the offset 0 (|o| <= r), so other offsets are infinitely far (was a division by
  zero in every entry).
- `gaussian_matrix(p, [n1, ..., nd])`: the outer product of sampled one-dimensional derivative-of-Gaussian kernels
  ((-1/(s sqrt 2))^k H_k(t/(s sqrt 2)) e^(-t^2/(2 s^2))), each scaled so its correlation with t^k is k!; for an even
  order a multiple of the order-0 kernel first removes the total, which sampling and truncation leave nonzero (the
  derivative of a constant is 0). Radii and deviations per dimension as `[[r1, ...], [s1, ...]]`.
- Left: `alphabetic_sort` in other languages (collation tables), `groupings` with operator heads given as options,
  the `evaluation_monitor` of the optimizers (options are evaluated before the call, so `sow(x)` runs once), the
  missing-key result (`failure(missing_key, k)` is documented design). Tests: `mc-engine/tests/round38_lists.rs`.
